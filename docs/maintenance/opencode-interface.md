# OpenCode interface dependency list

Every place this project touches OpenCode, one row per dependency, with what happens if
the host changes it. Generated by reading `scripts/opencode_compat.py`, the
`CONTRACT` block in `plugin/skill-tracker.js`, and every `process.env` / path
construction in both languages — not from memory. If you add a dependency, add its row
here **and** its declaration in the compat module or `CONTRACT` in the same commit;
`test_every_declared_opencode_name_is_still_present_in_the_writer` proves a declared
name is still read, and cannot prove an undeclared read exists.

Legend — **blast radius**: `silent` = keeps running, records nothing (the worst kind);
`loud` = raises, refuses to start, or `skillt doctor` says so; `cosmetic` = a number or
label is wrong but the data is fine.

---

## 1. Hooks registered on the host

All eight are declared twice — once per language — and compared by value:
`HOOKS` in `opencode_compat.py`, `CONTRACT.HOOK_*` in the writer, registered as
`[CONTRACT.HOOK_*]: safe(CONTRACT.HOOK_*, …)` so each string occurs exactly once.

| Hook | What we take from it | Writes to | If it disappears |
|---|---|---|---|
| `tool.execute.before` | `hookInput.tool`, `.sessionID`, `.callID`, `.args`, `.model.providerID`, `.model.modelID` | `skill_usage`, `mcp_usage`, `plugin_usage` (pending row) | silent — no rows at all |
| `tool.execute.after` | `hookOutput.status`, `.metadata`, `.args` | same rows, completed | silent — every row stays in its before-state; a call that never completes leaves no row (M15) |
| `permission.ask` | `hookInput.type`, `.action`, `.pattern` | `status='denied'` path | silent — refusals stop being recorded |
| `command.execute.before` | `hookInput.command` | `plugin_usage` (`kind='command'`) | silent — plugin commands stop being recorded |
| `event` | the bus events in §2 | see §2 | silent |
| `chat.message` | `props.info` | session/message linkage on the row | cosmetic |
| `chat.params` | `hookInput.*` for the parameter view | `metadata.model`, `metadata.agent`, `metadata.branch` | cosmetic — the columns go null (M16 freezes `branch` the same way) |
| `dispose` | nothing; it flushes and closes | — | loud-ish: rows already written survive, the WAL may not checkpoint |

The pair `permission.ask` (hook) / `permission.asked` (event) is **not** a duplicate:
different mechanisms, similar names. A rename of one does not imply the other.

## 2. Bus event types switched on inside `event`

| Event | Payload read | Why it matters |
|---|---|---|
| `session.created` / `session.updated` | `props.sessionID`, `props.info` | session identity for the row |
| `vcs.branch.updated` | `props.branch` | the `metadata.branch` key |
| `message.part.updated` | `props.part`, `part.state`, `part.callID`, `state.input`, `state.time`, `state.metadata` | the second write path for a subagent run — both paths write and `UNIQUE(parent_session_id, call_id)` folds them into one row |
| `permission.asked` → `permission.replied` | `id`/`permissionID`, `requestID`/`permissionID`, `reply`/`response`, `tool.callID`/`callID` | measured on 1.18.33; the SDK's spelling (`permission.updated`) is still accepted, and the handler tries each pair **in order** rather than deciding which is right |

## 3. Tool ids and identifier shapes the host owns

| Name | Value | Who declares it |
|---|---|---|
| skill tool | `skill` (`SKILL_TOOL`, overridable with `OPENCODE_SKILL_TRACKER_TOOL`) | compat + writer |
| subagent builtin | `task` (`TASK_TOOL`) — the **only** builtin recorded | compat + writer |
| skill argument | `args.name` (`SKILL_ARG_NAME`) | compat |
| subagent label | `args.subagent_type` (`TASK_AGENT_FIELD`), admitted only through `SUBAGENT_LABEL_RE` (no space, no path, ≤ 40 chars) | writer |
| MCP id shape | `{server}_{tool}`, longest-prefix match against the detected server list (`MCP_ID_SEPARATOR`) | compat + writer |
| MCP permission marker | prefix `mcp:` (`MCP_NAMESPACE_PREFIX`) | compat + writer |
| builtin allowlist | `invalid,question,bash,read,glob,grep,edit,write,task,webfetch,todowrite,websearch,skill,apply_patch` — pinned to 1.18.34 | writer (`DEFAULT_BUILTIN_TOOLS`); the *claim* about the release is `PIN_TOOL_IDS` in compat, and the two are compared by `test_the_tool_id_pin_is_a_claim_the_plugin_actually_makes` |

A tool renamed inside the allowlist is the classic silent failure: it stops being
classified as builtin, so its calls get attributed to a plugin and land in `(unknown)`.

## 4. The host's filesystem

| Path | Read or write | Declared as |
|---|---|---|
| `~/.config/opencode/` | read (config, plugin dir, logs, skills) | `CONFIG_HOME`, `PLUGIN_SUBDIR`, `LOGS_SUBDIR`, `SKILLS_SUBDIR` |
| `~/.config/opencode/opencode.json`, `.jsonc` | read — to find MCP servers, plugin specs and the model/agent metadata source | `CONFIG_FILE_NAMES`; a parse failure is **never** treated as "empty config" (that is what would make a broken config look like "no plugins installed") |
| `~/.config/opencode/plugin/` | write target of `install.sh` only | `PLUGIN_SUBDIR` |
| `~/.config/opencode/logs/skill-tracker.log` | our own log, written by the plugin, read by `doctor` | `LOGS_SUBDIR` |
| `~/.local/share/opencode/skill-usage.db` | our database | `DATA_HOME` |
| `~/.local/share/opencode/backups/` | our backups, and the only directory retention may prune | `DATA_HOME` + `BACKUP_RE` |
| `<project>/.opencode/` | read (project-scoped config) | `PROJECT_CONFIG_DIR` |
| `<skill dir>/SKILL.md` frontmatter `name`, `description` | read | `SKILL_FILE_NAME`, `FRONTMATTER_*` |
| `~/.cache/opencode/packages/` | read (to resolve a plugin spec to a file) | `PACKAGES_HOME` |
| **`~/.config/opencode/opencode.json` is never written** | — | a hard rule, not a convention: it is the host's file, it is hand-edited, and our settings layer writes only `~/.local/share/opencode/skillt-config.json` |
| **`opencode.db` is never opened** | — | considered and declined; MAINTENANCE §8 records the deferred backfill and why |

## 5. HTTP and subprocess edges

| Edge | Direction | Rule |
|---|---|---|
| `GET /experimental/tool/ids` | out, **only** during a manual refresh of the allowlist, against `opencode serve --pure` | never from the plugin, never from the TUI. The recipe is MAINTENANCE §5 |
| `http://127.0.0.1:<worker port>` | out, claude-mem's own worker, headless commands only | one shared deadline for the three endpoints, field-name **and** type whitelist (`_numbers_only`), no path or free text crosses it |
| `opencode --version` | out, `skillt doctor` only | a subprocess, so CI and this shell both need it on `PATH`; when it is absent the check WARNs with "`not on PATH?`" — an instrument statement, not a version claim |
| `os.kill(pid, 0)` | local, worker liveness from `worker.pid` | allowed on the repaint path precisely because it is a syscall, not a request. `startToken` in that file is parsed and never emitted |

Nothing else in this project opens a socket. There is no telemetry, no update check, and
no dependency that may put message content on disk.

## 6. Environment variables the writer honours

The read side (`OPENCODE_SKILL_TRACKER_SKILLS_DIR`, `…_BACKUP_DIR`, `…_CONFIG_DIR`,
`…_STREAMS`, `…_LOG`, and the `log.*` / `view.*` / `retention.*` settings) is documented
in README's settings table and gated by `test_no_environment_variable_is_read_without_being_documented`.
What follows are the **writer-side kill switches and pins**, all read in the plugin:

`OPENCODE_SKILL_TRACKER_DB`, `…_DISABLE`, `…_MCP_DISABLE`, `…_PLUGIN_DISABLE`,
`…_SUBAGENT_DISABLE`, `…_MCP_SERVERS`, `…_PLUGINS`, `…_PLUGIN_EXCLUDE`,
`…_BUILTIN_TOOLS`, `…_TOOL`, `…_LOG`, `…_DEBUG`.

`HOME` is inherited, not a knob: every default above is built from it. `TMPDIR` is where
`__selftest()` makes its throwaway database.

## 7. The export contract, because it is the one thing that can stop everything

`plugin/skill-tracker.js` must export **only** `export default { id, server }`. On
1.18.32 the loader calls every exported function as a factory and stops only when the
default export is an object carrying `server`; a named `export function` (including
`__selftest`) gets called as a factory, its isolation guard throws, the whole plugin load
aborts, and recording stops silently for every stream.
`test_loader_does_not_enumerate_exports` replicates the loader logic to keep that true.
